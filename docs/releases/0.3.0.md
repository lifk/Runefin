Runefin 0.3.0 adds **downloads**, and makes Home cheaper to build on a server with many libraries.

**Downloads.** A **Download** action sits on every film's and episode's page, and a series page
downloads the episode Play would start. What lands is the item's own file — nothing is
transcoded unless you ask — written with a resumable partial file, so a quit, a crash or a pause
continues at the byte it reached.

The **Downloads** page lives under Tools: each row shows its state, progress and size, with Play,
Pause/Resume or Retry, **Keep** and Remove. Keep pins a copy: when a new download needs room, the
oldest finished copies that were not kept make space, and one that still cannot fit is refused
with the shortfall instead of starting.

**Offline.** A finished copy plays through the same in-app player straight from the file. It
reports to the server while one is reachable and plays anyway when it is not: the page and its
rows come from a manifest on disk, so a download is usable with no server at all.

**Choose the size.** Settings → Downloads has the folder (default
`~/.cache/runefin/downloads`), a storage budget (20 GB to start), the free space beside it, and
**Download quality**: **Original** keeps the file exactly as the server stores it, and a bitrate
(20 / 12 / 8 / 4 / 2 Mbps) asks the server to make a smaller copy. That copy is one progressive
MP4, made while it downloads, and it cannot resume after a pause — pausing ends the transcode, so
resuming starts it over. The row says `4 Mbps copy`, and the size shown before it finishes is an
estimate from the runtime and the cap.

**A bug the first real download found.** The client's HTTP agent bounded a *whole request* at
thirty seconds, body included. A 4 GB file takes longer than that, so every download would have
died halfway — this release clears that deadline for a stream while still ending one that stalls.
The first end-to-end run: a 24-minute episode at 2 Mbps, 307 MB, in 166 seconds.

**Home builds only what you can see.** Home's rails are now virtualized: the rails near the
viewport are built, the rest when you scroll to them. On the demo server that is 450 layout nodes
down to 354 with identical pixels, and the saving grows with the number of libraries. The engine
gained a per-list overdraw setting for it (a Home rail is over half a screen tall, so the engine's
default of two screenfuls each side mounted nearly the whole page); the Rune revision moved to
`83cda583` for it, with no visual change.

**Everything from 0.2.2 carries over**: scRGB HDR output with its SDR fallback, HDR video that
keeps absolute PQ/HLG light on an HDR display and tone-maps on SDR, `runefin://` links, the
optional Decky Quick Access Menu companion, trickplay previews, true hairlines, and the engine's
focus work.

## Install

```sh
flatpak remote-add --if-not-exists --user runefin https://lifk.github.io/Runefin/runefin.flatpakrepo
flatpak install --user runefin io.github.lifk.Runefin
```

Or the offline bundle attached to this release:

```sh
flatpak install --user ./Runefin-0.3.0-x86_64.flatpak
```

HDR needs a compositor that advertises an HDR format (KWin on Wayland in Desktop Mode); SteamOS
Gaming Mode does not offer one to a native Flatpak, so the app stays SDR there.
