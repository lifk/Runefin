Runefin 0.2.2 is an engine release, plus two small refinements.

**A new UI engine.** Rune moved 143 upstream commits forward — it is now a split workspace of 25
crates — and what changes is felt rather than seen:

- Focus no longer resets when a rail rebuilds or new data lands, so a card's ring and its motion
  stay put while Home fills in.
- A rail is **one Tab stop**, not one per card, and a control that becomes disabled hands focus
  on instead of stranding it.
- Nested focus groups (a chip row inside a rail, the gear sheet inside the player) traverse
  correctly.
- Video decoders share the engine's task threads; shaders evaluate at exact pixel centres, which
  moves a handful of pixels per screen by a single step; tooltips open on keyboard focus; a
  notched wheel glides on Chromium's curve; a touchscreen tap can be told from a mouse click.

**Everything from 0.2.0 and 0.2.1 carries over**: scRGB HDR output with its SDR fallback, HDR video
that keeps absolute PQ/HLG light on an HDR display and tone-maps on SDR, `runefin://` links, the
optional Decky Quick Access Menu companion, the trickplay work, and the faster cold start.

**Two refinements.** Horizontal rules are true hairlines now — half a point drawn on whole device
pixels, so a divider stays a rule at 1.5× and 3× instead of thickening to two or three pixels. And
the search field's focus ring is drawn by the engine while focus is within it: the same accent
ring, with no state to drift.

No visual redesign: the committed views differ only in the divider's own row.

## Install

```sh
flatpak remote-add --if-not-exists --user runefin https://lifk.github.io/Runefin/runefin.flatpakrepo
flatpak install --user runefin io.github.lifk.Runefin
```

Or the offline bundle attached to this release:

```sh
flatpak install --user ./Runefin-0.2.2-x86_64.flatpak
```

HDR needs a compositor that advertises an HDR format (KWin on Wayland in Desktop Mode); SteamOS
Gaming Mode does not offer one to a native Flatpak, so the app stays SDR there.
